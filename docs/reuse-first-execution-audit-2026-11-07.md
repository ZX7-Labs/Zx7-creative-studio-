# ZX7 reuse-first source audit — 7 November 2026

**Source actually inspected:** `main` at `440511d989b042ceeee8954b860a587bd5ef4ea2` and the existing [architecture](architecture.md), [reuse research](reuse-research.md), [A–L scope](../CAPABILITIES.md) and [engineering standard](../ENGINEERING_STANDARD.md). Main's recursive source tree contained **143 non-test Python files under `studio_next/`**. Byte sizes below are files, **not measured hours or development effort**. This is a targeted source review, not a proof that every integration is production-ready or a repository-wide dependency audit.

**Decision:** stop extending homemade versions of creative engines already available from complete, independently licensed open-source applications. Preserve correct owner-data custody, grants and native project history. Replace a custom primitive only after an equivalent mature operation has been tested for **full** semantics, including precision, editable state, physical output, memory and performance. A mature library is not automatically faster or more faithful.

**False shortcut to avoid:** switching to a different editor or framework solely because it sounds more advanced. Earlier direct comparisons [documented here](reuse-research.md#whole-editor-source-selection) rejected OpenKatana as a multitrack NLE and retained NodeTool as a viable *alternative*, not a mandatory second stack. The actual first complete Velorn integration is already tested. A stack migration requires a same-workload differential and a strictly better result.

## The first implemented reuse experiment in this branch

- **Opt-in only** `VisualGraph(..., convolution_backend="scipy")` and `render_visual_graph(..., convolution_backend="scipy")` use the mature SciPy native compiled implementation. Default remains `numpy`, preserving every current project and caller.
- Install only when selected: `python -m pip install '.[production,visual_acceleration]'`. No SciPy mandatory runtime weight is imposed on video-only, 3D-only, server or source-custody workers.
- Explicit two-axis kernel orientation, signed/asymmetric weights and modes `transparent=constant-zero`, `clamp=nearest`, `wrap=wrap` retain the original NumPy semantics. Output stays float32 linear associated-alpha, not an 8-bit conversion.
- The physical render receipt declares its backend and library version; project JSON and native node fingerprints are unchanged. Backend-specific floating-point round-off remains possible; **pixel-by-pixel byte identity is not asserted for all images**. Tests compare linear RGBA with strict tolerances, require actual original editable plan immutability and decoded PNG agreement within one 8-bit code value.
- Source CI has a dedicated optional engine job that installs the declared SciPy extra and measures one real workload. It records times without imposing a noisy machine-dependent speedup threshold. The original NumPy branch is still available, not deleted.

## Research-backed next reduction experiments

1. **Agent-loop reuse before adding more handwritten planner code.** Put a Pydantic AI typed agent or LangGraph loop *behind the existing host-gated MCP adapter* (currently draft PR #209), with the same model, source, native application, host grants and safety ledger. Measure actual model turns, tool choices, wall time, CPU/RAM, saved native project, observation, revision and export. Stop if it duplicates, automatically retries, loses an authorized/native effect or makes unsupported artistic success claims. Do not introduce a framework merely to rename the 103 KB current implementation.
2. **Use existing complete native authoring systems for graphics/3D.** Test Inkscape original editable SVG with a targeted revised vector artifact, and Blender RNA 3D native saved/reopened scene. Do not claim graph-only preview or film render constitutes professional graphic/3D completion. Prefer the installed engine's tool schema.
3. **Avoid parallel scheduler and document formats.** Keep ZX7's already-tested durable owner-state/SQLite and host admission; do not bring in Temporal, a message broker or extra database until cross-process agent demand and idempotency can be demonstrated. Any future orchestration framework must keep the no-automatic-replay uncertain-write guarantee.
4. **Verify creative completion, not tool count.** The genuine local Qwen4B original-camera retry and saved native edit are *separate* from this filter experiment. Never claim SciPy speed improvements solve autonomous editorial planning or artistic evaluation.

## Premortem / engineering cost gate

- **Risk:** SciPy changes alpha/edge semantics. **Response:** explicit backend and equal native source/PNG differential; refuse production if unacceptable.
- **Risk:** faster single filters but slower total project or larger RAM. **Response:** benchmark by kernel/canvas under a real workload, include installation and memory, retain old engine if net negative.
- **Risk:** adding agent libraries weakens native write safety. **Response:** host gate and exact durable request IDs remain authoritative, even if a framework internally retries an activity.
- **Risk:** repeated 'reuse' migrations delay delivery. **Response:** no whole-engine rewrites; one physical comparison at a time with a failure/kill condition, preserve saved projects and branch history.
- **Risk:** rights or source licenses are conflated. **Response:** project/root license, GPL Velorn source, BSD SciPy, Blender and model weights have independent provenance and distribution obligations.

**Completion status:** This is a code-review and technology decision record, NOT the complete ZX7 project. The selected SciPy path is only enabled by an explicit trusted host choice and must earn exact-head CI before merging. No universal lifetime budget, multi-domain professional quality or autonomous creative finish is claimed.
