# ZX7 engineering entry point

Build one local-first, free/open-source creative BODY operated by a replaceable Brain. Preserve the full original A–L professional scope. No reduced MVP, parallel replacement engine or scripted creativity counts as acceptance.

## Read in order

1. [BRIEF](project-brain/BRIEF.md) — owner intent and current authority/consent.
2. [STATE](project-brain/STATE.md) — the only human current status, canonical workstream and next action. Refresh live GitHub source, main, PR and CI.
3. [Typed ledger](project-brain/EXECUTION_LEDGER.json) — the same snapshot in machine-readable form; read relevant entries.
4. [Build blueprint](docs/BUILD_BLUEPRINT.md) — relevant fixed requirement and acceptance gate. [CAPABILITIES](CAPABILITIES.md) and [ENGINEERING_STANDARD](ENGINEERING_STANDARD.md) retain original authority. [Master Plan](docs/ZX7_CREATIVE_STUDIO_MASTER_PLAN.md) preserves original rationale and G2 hypothesis. [Document map](docs/DOCUMENT_MAP.md) indexes all references.

## Work rules

- Whole A–L studio is the active product scope. Prioritize measured shared and domain-specific dependencies, not a mandatory video-first sequence. Runtime Brain attachment must use executable discovery, typed contracts, live state, actions and feedback—not runtime Markdown or engineer-written creative prompt packs.

- Use the canonical workstream in STATE. Before editing, inspect current source, branch/PR overlap and latest positive and negative evidence. Never recreate working behavior or merge historical experiments merely because paths differ.
- Preserve exact archive; reconcile integrity, safety, data-loss, current workload and release-critical behavior. Do not block product-critical work on unrelated historical variants once a verified baseline exists. No branch deletion. Apply [blueprint §8](docs/BUILD_BLUEPRINT.md#8-required-engineering-method-for-every-implementation-task): isolate the actual blocker, reuse known-good behavior, move justified deterministic coordination off the model, and require matched outcome evidence. Focused checks before full stable-candidate verification.
- Normal work: reproduce real defects, reuse mature pinned engines, make minimal tested changes, verify installed outputs and failure/recovery. Source, offline tests, physical output, genuine AI decisions and independent professional acceptance are separate tiers.
- Keep host grants and budgets bounded. Never guess or replay uncertain writes, upload private owner data, expose credentials or start hosted inference through normal CI. Follow latest specific consent in BRIEF.
- At meaningful checkpoints update STATE and the ledger together (exact ledger blob binding); link evidence once, update risks or append decisions only on changed facts. No third current status, diary, handoff or competing product plan.

[Working agreement](docs/continuity/WORKING_AGREEMENT.md) and [Project Brain](project-brain/README.md) define execution/update discipline.
